Backend (done, uncommitted working tree): each selected idea now gets a single-file HTML website generated by the LLM (create-idea-site prompt, reasoning enabled, 32k output budget). Websites start right after each refinement commits and generate concurrently with per-idea research and evaluation; the idea job (and therefore the debate) only completes after all websites settle. Pages persist as files at IDEA_SITES_DIR/<idea_uuid>/websites/index.html (written only on full completion, so no partial pages) and are served at GET /api/idea-jobs/:ideaJobId/ideas/:ideaId/website under the same read scope as the job detail (owner, or anyone for a public debate) with CSP sandbox allow-scripts, nosniff, and no-store headers because pages are model output. A website failure fails the job with the new website event stage; replay derives that stage and the client maps it to the improvement progress card.

Findings from review discussion: (1) the debate does NOT start before websites finish - debateTournamentEffect awaits ideaCompletion, which resolves only after all website generations settle, so the debate start is strictly gated on websites (latency is mostly hidden because sites generate in parallel with research/evaluation); (2) the frontend has no live website progress - generateIdeaSite publishes no stream event, setEventStage(website) is only a local variable for the terminal error label, and the progress card derives stages purely from stream IDs and data events, so the client sees an opaque running improvement card until done; the website literal in the client schema exists only to parse the failure stage.
