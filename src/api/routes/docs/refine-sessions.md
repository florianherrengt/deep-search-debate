# Refine sessions

Refine sessions are private, owner-scoped records mounted behind session authentication. `POST /api/refine-sessions` creates a session from `{ prompt }` and immediately starts its first preparation batch. `GET /api/refine-sessions` lists the caller's sessions; `GET /api/refine-sessions/:id` returns a canonical snapshot.

A snapshot includes the immutable original prompt, session state (`clarifying`, `starting`, or `research-started`), batch history, current `draftAnswers`, preparation-search links, and the final research link once handed off. A preparing or failed batch has a `pendingBatchId`; `currentBatchId` is set only while a ready batch accepts answers. Draft updates use `PUT /:id/draft` with `{ batchId, answers }`. `POST /:id/batches` submits answers immutably and opens the next batch. `POST /:id/retry` explicitly retries a failed current batch. `POST /:id/research` atomically reserves and starts the ordinary standalone deep search. Mutations return `{ refineSession: snapshot }`.

Answers may select multiple candidate IDs and include free text. Missing answers and empty selections are stored as unanswered. Older batches are immutable. Repeating a batch submission or final handoff with the same IDs and answers is idempotent. A start request may carry the just-submitted previous batch ID if it races an Ask more request; the manager uses the latest durable answers and cancels the active preparation. A failed preparation remains failed until explicit Retry, including after restart.

Preparation searches are ordinary deep-search roots with an explicit `refine_search_links` association. Automated-research history exposes these as Refine-origin jobs. Generic root recovery excludes all Refine preparation links; the Refine manager resumes only active preparing work and leaves failed batches waiting for Retry. The final search is linked atomically to the session and remains an ordinary manual research root for startup recovery. Refine sessions become read-only after the durable handoff begins; the resulting research remains accessible through its normal deep-search route.

The controller persists append-only shared-state revisions and per-batch stage checkpoints. It gathers deep-search evidence before proposing questions, re-enters callable controller stages using their saved dependencies, and only performs targeted additional research when its typed action requests `TOOL_WORK`, bounded by configured deep-search limits. Each provenance-producing stage receives a stage-scoped catalog of verbatim evidence excerpts. Model outputs must reference exact catalog IDs; the controller validates each ID and resolves it to canonical excerpt text before checkpointing or updating shared state. Confirmed user requirements, recovered known facts, and domain findings require non-empty exact excerpts from their permitted source context before a stage can complete. User evidence includes the original request, selected candidate labels, and supplemental answer text; assistant question wording and unanswered records cannot support a confirmed claim. Unresolved requirements, derived decisions, needs, and assumptions may lack supporting excerpts; any supplied excerpts must still match their permitted sources. Existing quote-based checkpoints remain valid and are checked against their original source context.

The user decides when to end clarification: empty or poor batches still leave both Ask more and Start research available. Preparation and final research requests include the original prompt and all submitted answers; final handoff explicitly marks unanswered questions. Requests within the configured research limit pass through unchanged. Oversized requests use the selected Big model to condense requirements, selections, supplemental text, corrections, and unanswered questions into a bounded research prompt. The complete original prompt and immutable answer batches remain saved in Refine. Condensation uses ordered source excerpts and a rolling brief under the existing summary-context limit, so unlimited batches do not create an unbounded model call. Each validated chunk is checkpointed with its generation; completed chunks are reused after failure or restart.

Start reserves the final search and captures its source record before cancelling preparation. Condensation and research preflight run outside the database transaction; the bounded request is saved before the ordinary deep-search job starts. A condensation failure during preparation leaves that batch failed until Retry. A final condensation or preflight failure restores the clarifying session with its immutable answers and Start research available for an explicit retry. Invalid structured output fails without repair, truncation, or automatic application retries.
